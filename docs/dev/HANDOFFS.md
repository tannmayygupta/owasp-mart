# Handoffs: what one developer leaves for another

Raw material from the contract work of Tanmay (stream L, stories L-02, L-03, L-04). Read the rows addressed to your task when you plan it.

## How this works

1. A **handoff** is one thing a developer must confirm, decide, build against or carry over. Each has an id (H-01, H-02 and so on), a from and a to developer, the task id(s) it belongs to, a source, a default and a status.
2. **Default** means: if you say nothing and implement, this proposal stands. It is quoted from the contract; "no proposal yet: needs a decision" means nobody has proposed one.
3. **Status** is `open`, `confirmed`, `changed`, `answered`, `answered, to re-confirm` or `done`. Write your reply in the **Answer** column.
4. The owner of a task reads the rows addressed to that task when planning it (START-HERE.md, step 2a), asks the developer to confirm or change each one, and writes the answer here.
5. If an answer changes a contract, tell Tanmay (contract owner) in the team chat; the contract is then updated by pull request. Pull request review is optional (D-37).
6. All rows start `open`. Every handoff row of a task is also pointed to by a `Handoffs:` line under that task in the task file.
7. Source key: **IF-6** = `contracts/instance/instance-contract.md`, **IF-4** = `contracts/events/app-events.md`, **IF-5** = `contracts/orchestrator/orchestrator-api.md`; **OP n** = row n of its "Open points (to confirm)" table; **s5** = section 5 of that file; **ADR** = `docs/adr/`; **D-nn** = `initial.md`; **arch 07** = `docs/architecture/07-repo-and-workstreams.md`.
8. **Renumbering (2026-10-18):** stream L (Tanmay) and stream P (Akshay) created handoff rows H-127 to H-134 in parallel, with different content. When `main` was merged into `sprint-3-tanmay`, stream L's rows (H-127 to H-147) were renumbered by adding 200: stream L's old H-127 is now H-327, and so on up to H-347; stream P's H-127 to H-134 keep their ids. Old references in earlier chat messages or outside this repository mean the +200 id for stream L. **Rule from now on: stream L takes new ids from H-348 upward, stream P continues from H-135; never reuse a number the other stream may have taken.**
