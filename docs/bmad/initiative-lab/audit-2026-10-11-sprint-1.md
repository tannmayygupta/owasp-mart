## Blockers and highs found, with what was done on 2026-10-11 (story 1.13) and what is left

### Fixed or recorded in story 1.13 (before the pull request)
- Stale or false statements: traceability rows LB-5, LB-6, LB-7, LB-9, LE-1, LE-6, LE-8; dev-log headers saying "uncommitted" or "not closed"; ADR 0022 status "nothing applied"; CHANGELOG false line, glued heading and eaten characters; control characters in three documents; BOM and mojibake files; HANDOFFS H-101 gap and invalid statuses; D-15 and D-34 not marked superseded by D-41.
- Task ticks that outran their Done-when (L-02 approval, L-05 consumer review, L-08 follow-ups, L-04 and L-07 CI never run): the ticks stay (the developer closed them) but each now carries a dated note listing the waived or open item and where it is tracked.
- CI first-run hardening: `scripts` job timeout, `concurrency` cancel only for pull requests, the L-01 end-to-end test added to a CI job, reason for the other excluded end-to-end file written down.
- Security hygiene: `image.png` (shows an account ID) ignored and refused by the secret scan; IAM policy tag conditions on stop, start, terminate and modify (instance-type bypass through `ModifyInstanceAttribute` is a known residual risk, see below); host firewall check names say "placeholder rules"; runbook warning not to rerun the firewall script on a host that runs Docker.

### Left open on purpose (backlog, in priority order; each becomes a bug or contract story)
1. **IF-4 sequence and epoch rules (BLOCKER for L-13, L-18):** `first_seq` = highest stored seq + 1 versus the reserved range from 2^40 for orchestrator and platform events; the first stored orchestrator event makes the next `first_seq` land in the reserved range; the wire event has no epoch so buffered old events collide with the new epoch; the schema has no per-source seq rule (an orchestrator event with seq 1 is accepted).
2. **Event key lifecycle (BLOCKER for the real ingest and KeyPort):** H-09 (derivation) and H-10 (distribution) have no proposal; open point 33 allows a new key at reset while the fake ingest keeps one key per instance.
3. **IF-6 template schema (HIGH):** accepts shop with `network_mode: none`, component named anything, env values pointing to any URL or path, health path `/healthz` for the shop, unlimited memory, cpu and pids, ports and health checks on the injector, `vm.expires` and uid out of range, a shop with the injector image, a 20-character "reason". Fix with `const`, patterns, maximums and semantic rules.
4. **IF-5 contract gaps (HIGH):** `StateReport` has no transition number (duplicates indistinguishable); `seq` accepts `1.0` and `1e0` (signing string differs by language); `Problem` is closed so adding the RFC 9457 members is breaking (story 1.12); the fake and the HTTP service disagree on booleans as integers, fingerprints of `2.0` and `2`, garbage cursors; the shared protocol suite pins none of them; the HTTP client accepts any `ssl_context` including one without verification.
5. **IF-2 contract gaps (HIGH):** timeline pagination by offset is wrong for late, out-of-order events (needs a stable sequence); no visibility heartbeat route (FR-INS-03); deadline does not make an attempt non-running and the mock never expires one; role rules undefined (any role can request an instance); states `withdrawn`, `deleted`, `cancelled` unspecified for reads; lists capped at 100 with no truncation marker; no way to recover an instance id after a lost 202; flag oracle names `decoy`, `other_instance`, `stale_epoch` to the submitter and does not count them toward the rate limit; contract and mock disagree on the order of the 415 and 404 checks.
6. **Stub and conformance (HIGH):** `/_stub/planted-flag` is a test route reading a file the harness wrote; the conformance check is a hand-written rule list, not the `instance-template` schema, and its helper-name allowlist can be used to skip rules; the sidecar ignores `flag_digests` and `epoch`; IF-4 signing is verified by the module that signs; "ready only after the marker" holds by start order in the harness; overflow drops any event type, poison events block the queue, `seq` is in memory only.
7. **Rules engine L-07 (HIGH):** a whole contract can be deleted with no BREAKING line; `mocks` and `noMock` are read only from the pull request head (can be switched off); oneOf branch removal can pass; checker, registry and workflow come from the pull request itself; self-attested BREAKING matches "not BREAKING"; unlisted `.json` or `.yaml` artefacts escape; tag baseline never runs (no tag); several false positives on valid changes; oasdiff pin is trust-on-first-use from GitHub and the unit tests download it (GitHub outage turns every pull request red).
8. **Host security L-08 (HIGH):** containers on the labs host are not isolated from the platform host, the host's own ssh or the VPC (H-103: DOCKER-USER policy, egress control, second subnet); IAM stop, start and modify actions allow changing the instance type of tagged instances (`ModifyInstanceAttribute` cannot be limited by type here); the idle alarm and budgets only warn; first boot with the fixed scripts never ran clean (both hosts were repaired by hand: rebuild the labs host once with `-replace`); the stop and start path never rehearsed live; keep-alive on would starve the platform host; one SSH source address on a home connection (dynamic address risk), one key installed, local state with no named backup location; Oracle Terraform still runs in CI.
9. **Process:** many handoffs are open (H-24 to H-35 for Sahil, H-84 to H-103 for Akshay); under D-37 nothing forces an answer: someone must close the IF-4 and IF-5 rows before L-13 and L-18 start. Sahil's branch `sprint-1-sahil` conflicts with this one in `ci.yml`, `CHANGELOG.md`, `docs/adr/README.md`, `docs/traceability.md`, and both branches use ADR numbers 0017 and 0018.
