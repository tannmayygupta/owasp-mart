## Intent
Make the lab's state survive a restart. The engines kept attempts, scores, events, held captures and evidence only in memory.

## Acceptance criteria
1. Migration 0005 creates the lab tables (names from contracts/db/table-owners.yaml, five added) and the app role gets only the rights it needs.
2. Postgres stores implement every in-memory store; the runtime takes them as one bundle.
3. A real KeyPort seals evidence with AES-256-GCM under a per-attempt key stored wrapped; derived keys are stable across restarts.
4. The flag rate limit and the held-capture finality come from stored rows, not process memory.
5. When a withdrawn attempt reaches `deleted` the lab data of the attempt is purged.

## Plan
Models and migration (autogenerated, then grants); `vulnmart.lab.pg`; `vulnmart.lab.keys`; `LabStores`; runtime refactor so nothing reaches into a store; tests on a real Postgres as the app role.

## Result
Done. 16 tests in `apps/api/tests/test_lab_pg.py` on Postgres 18 pass, plus the migration, owner and settings tests. Defect found on the way: nothing created the attempt key, so every evidence capture would have been dropped as "no key"; the runtime now creates it at start. Not persisted on purpose: the pairing buffers of the evidence recorder and the pending M2 windows of the milestone engine (seconds-long; a restart replays the success events), and the orchestrator state history (the orchestrator resends).
