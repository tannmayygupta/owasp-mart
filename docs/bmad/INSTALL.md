# BMAD in this repo: install record

Installed 2026-10-08 by tannmayygupta with Claude Code, after a source review. Decisions: D-29 to D-31 in `initial.md`.

## What it is
BMad Method ("Agile AI-Driven Development"), MIT licence, from [github.com/bmad-code-org/BMAD-METHOD](https://github.com/bmad-code-org/BMAD-METHOD). It is a set of **skills**: instruction files (`SKILL.md` and references) plus Python helper scripts that Claude Code reads and runs. Version **6.13.0-next**.

## Source and pinning
- **Pinned commit:** `bda3c5929f672019b90f39a3ea27259d35d00974` (2026-10-06).
- **How it was installed:** the reviewed skill folders were **copied** from that commit into `.claude/skills/`. We did **not** run the unpinned `npx skills add` command, because it fetches whatever is latest and runs a package we had not reviewed.
- **Tamper check:** `docs/bmad/skills.sha256` lists a SHA-256 hash for every installed file (217 files), computed after converting line endings so it matches on Windows, macOS and Linux.
  - Verify any time: `node scripts/verify-skills.mjs` (prints OK, or lists changed, missing and extra files and exits with 1).
  - Tested both ways on 2026-10-08: it passes on the installed files and fails on a corrupted manifest line.
  - Regenerate only after a **reviewed** update: `node scripts/verify-skills.mjs --write`.

## Review findings (read-only review in an isolated folder, nothing executed from it)
- **Scripts:** only `bmad/scripts/setup.py` can reach the network, and only to compare versions against `raw.githubusercontent.com`. The other scripts run `git` (retrospective evidence) or local helpers. No script edits `settings.json` or hooks, and none asks for elevated permissions or bypasses prompts.
- **`setup.py`** works in a staging folder inside the project and swaps it in atomically; it deletes only skills that the module records mark as retired.
- **Web addresses in the installed files:** documentation links, template examples, and optional ticket-store configs for Jira, Linear, Notion and Trello (inactive unless someone configures them). We use the repo store.
- **Skills that ask the agent to offer `npx skills add ...`:** decline unless the team agrees.

## Runtime files
- `_bmad/` is generated by `bmad setup` (scripts and config). `_bmad/custom/config.toml` is our team override: tracker output folder = `docs/bmad`, project name = `owasp-mart`.
- `_bmad/custom/*.user.toml` is **gitignored**. Each developer sets their own `active_initiative` there, so each developer works in their own tracker folder.
- Trackers (BMAD ticket tree) live in `docs/bmad/initiative-<slug>/` as markdown files: initiative, epics, stories, plans.

## Prerequisite on every machine: `uv`
BMAD scripts run through `uv run`. Install once per machine: Windows `winget install astral-sh.uv`; macOS `brew install uv` (or the method on [docs.astral.sh/uv](https://docs.astral.sh/uv/)). Then open a **new** terminal so the PATH updates. Installed on Tanmay's PC on 2026-10-08 (uv 0.12.23, installer hash verified by winget). Still to do on Akshay's Mac and Sahil's PC.

## Rules
1. **Never auto-update.** Do not run `npx skills update -y` or accept an update prompt. An update changes instructions and scripts that run with your permissions. Review the diff against the pinned commit first, then change the pin, the hash manifest and this file in one commit.
2. Changes to `.claude/skills/**` and `_bmad/**` need review by a second developer. Run `node scripts/verify-skills.mjs` after every `git pull`.
3. These files are executable instructions: never paste secrets into a story, ticket or config.
