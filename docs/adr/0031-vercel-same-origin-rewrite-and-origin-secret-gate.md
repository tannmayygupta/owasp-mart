# 0031. Vercel same-origin rewrite with an origin secret, checked in Caddy and again in the application

- **Status:** Proposed (decided on the developer's delegation 2026-10-11, "delegated design, free things only"; recorded as D-50). Becomes Accepted when the developer confirms it after the live S-14 run.
- **Date:** 2026-10-11
- **Deciders:** Tanmay (stream L), on delegation (D-50)
- **Requirements:** LE-3, S-14, NFR-SEC-03, D-15, D-21, ADR 0002, architecture 03 sections 1.3 and 1.5, L-11, P-07, P-22

## Context
ADR 0002 made the browser talk only to the Vercel origin: a Vercel external rewrite proxies `/api/*` to the platform host on vm-p. The origin must accept only that traffic (a secret request header), and the live stream (SSE) must work through the rewrite (spike S-14). Nothing existed: no Vercel config, no gate in the platform Caddy, no S-14 check. The real dashboards (P-07) and the live certificates (L-10) are not there yet, so this story builds and proves locally everything that needs neither, and leaves the live steps to the developer.

## Options considered
1. **Vercel `routes` entry with a `request.headers` transform from a sensitive environment variable (chosen).** Documented by Vercel for this use; no compute on Hobby; the stream stays on the rewrite path; `set` overwrites a value a visitor sends.
2. **Routing Middleware or a Function that adds the header and proxies.** Costs function time (a Hobby function is cut at 300 s), and a stream through a function is the risky part. Kept as the fallback if the live run shows the transform misbehaving.
3. **Cross-origin direct calls with a CORS allowlist.** Rejected earlier (ADR 0002, NFR-SEC-03).
4. **A Vercel address allowlist at the firewall.** Not possible: Vercel publishes no address range (D7 below).

## Decision
- D1: the header `x-origin-secret` is set by a `routes` entry with a `request.headers` transform, `op: set`, `args: "$ORIGIN_SECRET"`, `env: ["ORIGIN_SECRET"]` (a sensitive Vercel environment variable). Only transform `args` are documented to expand environment variables, so `dest` is a plain URL: the committed file holds a placeholder host (`https://REPLACE-WITH-PLATFORM-NAME.duckdns.org/api/$1`, no secret, no real address) and `node scripts/check-sse-rewrite.mjs --render <origin> --out <dir>` copies the probe folder to a git-ignored folder with the host filled in, refusing anything but `https://<label>.duckdns.org`. No Middleware or Function proxy. The shape is checked offline by `--validate` (strict allowlist of every value; `routes` together with `rewrites`, `redirects`, `headers`, `cleanUrls` or `trailingSlash` is refused, because Vercel does not allow that combination).
- D2: the origin keeps the `/api` prefix (IF-2 uses `/api/v1/`, Caddy routes by prefix). The prefix-stripping line of architecture 03 (`rewrite to https://api.PLATFORM_ZONE/auth/login`) is superseded: the route destination is `https://<platform host>/api/$1`.
- D3: the Caddy gate (`infra/caddy/origin-gate.caddy`) matches the header exactly (Caddy has no constant-time compare), answers 403 otherwise, accepts two values for rotation (files `origin_secret_current` and `origin_secret_previous`, read at request time so a rotation needs no reload), never logs the header (deleted in the access log and in the default logger, whose proxy warnings print request headers: found by the e2e test), and refuses every request when a file is missing or empty (a header with an empty value must not match an empty file: an extra `header_regexp .+` line). The secret is exactly 64 lower-case hex characters (`openssl rand -hex 32`): a regexp on the header enforces it, and a secret file with any non-hex character is refused whole, because a file value that starts or ends with `*` is a wildcard in Caddy's header matcher (found while reviewing the gate, tested). The admin endpoint is a unix socket in the tmpfs (`admin unix//tmp/caddy-admin.sock`), not `admin off`, so that `caddy reload` (the certificate renewal hook of H-115) works; no TCP admin port. A secret file missing at container start makes Docker create a directory: the gate then refuses everything (tested) and the runbook preflight `test -f` catches it. The application repeats the check with a timing-safe compare: this is the real check, Caddy is the cheap first filter (handoff H-116 to Akshay).
- D4: SSE: heartbeat comment every 15 s, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, event ids, `retry`, no compression, no caching of rewrites; Caddy `reverse_proxy` with `flush_interval -1`. Vercel's documented rule is that a proxied request may stream while data arrives at least every 120 seconds.
- D5: stock Caddy image pinned by digest, no plugin (D-49); the certificate files come from L-10.
- D6: free only: Vercel Hobby (non-commercial use; coursework fits; recorded as a judgement of the developer to confirm), no paid add-on.
- D7: vm-p port 443 must be reachable from the internet because Vercel publishes no address range. It is published on purpose and is the only published port of this stack (H-100 and H-103 concern other ports and isolation and are not changed). The developer sets `public_web_cidrs` and applies; the secret is the protection, the gate and the application the control. Residual risk: only the secret stands in front of the application, stock Caddy has no rate limit, and there is no unauthenticated health endpoint for uptime monitors (runbook, "Residual risk").
- D8: the S-14 project is a throwaway static probe (`infra/vercel/s14-probe/`) deployed with the CLI after `vercel login` (no token in any file). Hobby Git deployment only accepts commits of the team owner, so real deployments are done by the owner.
- Files: `infra/caddy/Caddyfile.p`, `Caddyfile.test`, `origin-gate.caddy`, `compose.p.yaml`, `probe/server.mjs`; `infra/vercel/s14-probe/`; `scripts/check-sse-rewrite.mjs`; `scripts/e2e/caddy-origin.e2e.test.mjs`; runbook `docs/runbooks/vercel-and-origin.md`.

## Consequences
Easier: the gate and the unbuffered stream are proven against stock Caddy before anything is deployed; the live run is one command. Harder: the origin is on the open internet on 443 (only the secret and the gate stand in front); two secret files and a rotation procedure to run by hand; the application must repeat the check. Caddy sets `X-Forwarded-For` to the address of its direct peer, so the visitor address that Vercel sent is kept in `X-Edge-Forwarded-For` (only after the gate has passed).
**Limit of the `routes`-only shape:** `routes` cannot be combined with `rewrites`, `redirects`, `headers`, `cleanUrls` or `trailingSlash`. The probe needs only `routes`, but the real dashboards need security headers and perhaps a single-page fallback. The fallback is Routing Middleware (all plans) setting the header next to `rewrites` and `headers`; if the live test shows that rewrites with `headers` and a transform coexist, that shape is used instead. S-14 has a step for it (runbook Part G) and Akshay is told in H-116.
**Not proven (needs the live run):** that Vercel passes SSE through a rewrite unbuffered; the longest total stream length; which Host header Vercel sends; that `$ORIGIN_SECRET` expansion and the header overwrite behave as documented; `Set-Cookie` passthrough; that rewrite caching is off for the route (architecture 03 also mentions the header `x-vercel-enable-rewrite-caching: 0`; the cache check of S-14 decides whether it is needed); Hobby usage counted by a held stream. If the live run fails, the fallbacks are Routing Middleware for the header (option 2) and the plan B of architecture 03 section 5 (ticketed direct stream), which is the developer's call.
